# BXH ARENA v13.29.5

本包前端為 **13.29.5**，搭配已部署的 **13.29.4 Functions / Firestore Rules**。
本次無須重新部署 Functions 或 Rules，也不需要重新建立資料庫、清除賽事或重建對戰表。

## 本次更新

- 每日簽到新增獨立分頁，放在賽事大廳旁。完整日曆與統計移入分頁，大廳保留精簡入口。
- 簽到尚未開放時顯示說明，讀取失敗時提供重新連線。
- 修正跳過場次每次重算都再往後延的問題：只記住跳過當時本台前兩個可執行場次，完成後接續。
- 跳過時本台沒有其他可執行場次，則保留在待承接清單，避免立刻又回到原台。
- 裁判頁新增待承接清單。裁判可承接至有操作權限的台次，管理者可指定台次。
- 目標台閒置時立即承接；目標台正在比賽或暫停時，保留目前場次，承接場排入之後。多筆承接依承接先後排列。
- 保留選手、比分、得分紀錄與晉級關係。一般未跳過場次不能由待承接入口移走。
- 已安排承接的場次顯示安排狀態，不再提供重複承接按鈕；開始比賽後仍可再次使用跳過。
- 閒置台若有可承接場次，顯示承接提示，避免一律顯示等待晉級結果。
- 雲端場次操作改為由最新 Firestore 交易資料合併。承接驗證場次修訂、台次與目前角色，拒絕重複承接及舊台次的比分／結果寫入。
- 雲端尚未同步時暫停場次操作，失敗後重新讀回雲端狀態，避免留下未成功的本機比分。
- 後台連線診斷以「後端相容」呈現 .5 前端搭配 .4 後端。

## 更新方式

1. 先備份目前 GitHub Pages 的 `index.html`。
2. 用本包 `index.html` 更新原網站相同位置，依原本 GitHub Pages 流程發布。
3. 等待網站更新後，管理者與所有裁判裝置重新整理，確認畫面版本為 `v13.29.5`。
4. 使用測試賽事完成下列驗收，再投入現場。

本次只需更新網站 `index.html`。不要因壓縮包包含 `functions/` 就重新部署。
包內 Functions 程式與 Rules 保留 .4 版本，作為完整備份；Node 設定已對齊目前 Cloud Shell 使用的 Node 22。

## 現場操作

裁判在目前比賽按「跳過」，上方會出現待承接場次。
負責台 2 的裁判可按「承接至台2」；管理者可按「指派至台2」。
原台自動處理下一場，目標台已有比賽時不會被強制替換。
台次仍沿用既有裁判指派設定，本功能不會改動裁判帳號或授予新的帳號權限。

## 已驗證

自動化檢查在本機 Node v24.19.0 執行，通過：

- 全部內嵌 JavaScript 語法檢查。
- 跳過不持續往後延、重新載入後維持順序、單一場次保留待承接。
- 閒置／忙碌／暫停台承接、保留比分與紀錄。
- 單淘汰賽移台後，原晉級選手仍正確進入下一輪。
- 實際前端交易方法搭配模擬 Firestore：兩次競爭承接只有一次成功，私有資料與公開鏡像一併寫入；舊台次比分及結果確認被拒絕。
- 裁判台次、封存、停用帳號、一般玩家、封測自建與社群自建賽事界線。
- 每日簽到分頁的可簽到、已完成、未開放、連線失敗顯示。
- 既有登入、帳號管理、簽到去重、跨日跨月、稱號初始化保留、補算重試及帳號切換隔離回歸。

執行方式（在解壓後目錄）：

```bash
node test_courts.cjs
node test_behavior.cjs
node test_accounts.cjs
node test_auth.cjs
```

`test_emulator.cjs` 保留 .4 的匿名存取測試，本次沒有重新執行 Firebase Emulator。
交易測試採本機模擬，未代替實際 Firebase IAM／Rules 驗證；本次未連線改動正式專案，也未完成手機瀏覽器的實際互動驗收。

## 更新後待驗收

1. 兩台裝置同時承接同一個跳過場次：只能一台成功，另一台顯示狀態已改變。
2. 原台與目標台確認同一份比分；完成移台場次後，下一輪正常產生。
3. 受台次限制的裁判只能安排到自己負責台；管理者可指定其他台。
4. 手機獨立簽到頁按「今日簽到」，重新整理仍為已簽到，重複點擊不增加次數。
5. 在原本使用的單淘汰／雙淘汰／循環賽流程各跑一場測試，確認現場分台與晉級顯示。

所有裁判裝置都應使用 .5；.4 舊畫面不具備本次新交易與修訂檢查。
本版沿用既有「賽事 JSON」資料結構與 Rules。台次檢查是正常客戶端流程的保護，並未新增伺服器端逐場授權。
賽事設定、名單等管理操作仍沿用既有整份資料寫入流程；進行裁判操作時應避免同時重設賽制、名單或台數。
